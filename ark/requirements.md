## 一、背景与目标

### 1.1 背景

我们希望探索使用 Hermes Agent 搭建设计工作流，以提升设计效率，特别是在视觉设计方向探索、页面延展和 Design System 产出环节。

### 1.2 核心目标

1. **快速产出不同方向的视觉设计** — 基于确定的需求和交互稿，快速生成多个视觉方向供团队选择
2. **高效延展页面设计** — 确定视觉方向后，快速高效地延展剩余页面
3. **自动产出 Design System** — 从设计语言和具体页面设计中自动总结和产出 Design System

### 1.3 核心痛点

**风格迁移能力不足**：当前 DESIGN.md 格式对视觉语言的描述粒度不够，导致风格还原度不足，无法在不同产品和交互设计中可靠地复用视觉风格。

|--------|------|------|

### 3.2 各环节详细需求

#### Step 6: UI & Animation Design

**6.1 找视觉 Moodboard**
- 需求：搜集同行业/同风格的视觉参考
- 期望 Hermes 能做什么：自动搜集参考图、整理为 moodboard

**6.2 做视觉工作坊**
- 需求：基于 moodboard 探索多个视觉方向
- 期望 Hermes 能做什么：生成 3-4 个不同视觉方向的可预览方案

**6.3 提取视觉语言**
- 需求：从选中的 moodboard/视觉方向中提取视觉语言，产出一份 `.md` 文档作为视觉指导
- 格式参考：Google DESIGN.md（https://stitch.withgoogle.com/docs/design-md/format）
- 调整方向：基于 Google 格式进行扩展，解决风格还原能力不足的问题
- 当前 DESIGN.md 的不足：
  - 缺少视觉密度（留白比例、信息疏密）描述
  - 缺少图片处理方式（圆角、叠加层、裁切、滤镜）
  - 缺少阴影/深度系统（多层阴影、毛玻璃）
  - 缺少渐变模式描述
  - 缺少布局模式（常见页面结构）
  - 缺少动效规范（缓动曲线、时长、触发方式）
  - 缺少视觉参考图（AI 需要看图理解氛围）

**6.4 产出页面视觉设计**
- 需求：基于视觉语言指导 + 交互稿，产出具体页面的视觉设计
- 期望的输出物（两种可能性）：
  - **方案 A**：生成浏览器可直接预览的、精准还原视觉效果的前端可交互原型（HTML/CSS）
  - **方案 B**：连接 Figma，直接在 Figma 中产出视觉设计（需通过 Claude Code + Figma MCP 间接实现）
  - **方案 C**：先生成前端原型确认效果，确认无误后再挪到 Figma 中实现（A+B 的组合）

**6.5 动效设计**
- 需求：基于已产出 UI，延续同样的设计语言，产出动画设计
- 动效类型：
  - 元素微动画（图标悬浮/点击后的反馈）
  - 动态视觉效果（如音乐播放器背景中的动态发光光团）
  - 开机动画

#### Step 7: Design System

- 现状：没有现有 Design System，需从零开始
- 需求：从设计语言和具体页面设计中总结 Design System
- 期望的产出物：
  - Design Token 文件（结构化数据，给开发用）
  - Figma 中建好的 Design System
  - Figma 中 Design System 可视化
  - 用于说明的 Slides 文档

## 五、已确认的技术路径

1. **视觉语言文档格式**：基于 Google DESIGN.md 格式进行扩展调整
2. **视觉设计产出路径**：Hermes 生成 HTML/CSS 原型 → 确认效果 → 通过 Claude Code + Figma MCP 同步到 Figma
3. **Figma 连接方式**：Hermes 不直接支持 Figma，但可通过操控 Claude Code（支持 Figma MCP）间接实现
